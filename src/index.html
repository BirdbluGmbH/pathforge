Get a route in a few lines

PathForge is a drop-in route engine for the navigation you already have — it accepts your Grid, Tilemap, Hex layout, Waypoint set, triangle Mesh, or Unity's baked NavMesh and routes directly over them. For triangle meshes there is no grid and no extra bake step. This is a minimal, working single-agent query:

using UnityEngine;
using UnityEngine.Tilemaps;

// GridGraphBuilder: a present tile = blocked, an empty cell = walkable.
var builder = new GridGraphBuilder(grid, tilemap, 20u, 15u);   // width, height (cols, rows)
var solver  = new DnskSolver(builder.NumVertices);
solver.BuildFrom(builder, HeuristicMode.Landmarks);

uint[] buffer = new uint[512];                 // declare once, reuse — zero GC per query
var path = solver.QueryPath(startVertex, targetVertex, buffer);
if (path.Reachable)
{
    // buffer[0 .. path.PathLength-1] = the route (vertex IDs); path.Distance = total cost
}

Every PathForge type is in the global namespace — there is no using for a PathForge namespace. The buffer is yours to supply and reuse, so the kernel allocates nothing per query.

Why PathForge

A* is a commodity. What makes PathForge worth buying is how cleanly it integrates, how little it costs at runtime, and how easy it is to wire into the navigation systems you already have.

Zero GC per query

You supply a uint[] buffer; the kernel writes the path into it. No allocation, no GC spikes in tight loops.

Deterministic

Same input → same output. Critical for multiplayer lockstep and reproducible AI.

One field, many agents

Compute a field once; hundreds of agents read their next step from it in a single batched native call.

Works with your navigation

Grid, Tilemap, Hex, Waypoint, Mesh, and Unity's baked NavMesh — six adapters included.

Native, fast, safe

Rust kernel, C ABI, panic-catching FFI boundary, no third-party runtime dependencies. Measured against our own reference baseline on identical maps: 0 KB allocated per query (vs ~205 KB in the baseline) and ~1.9× faster route time.

It's the GPS, not the car

PathForge tells your units which way to go. You still drive — no animation, no steering, no collision.

Obstacles change at runtime? There is no incremental update — you rebuild the solver from your updated graph (or swap a pre-built field), and every agent on it reroutes. The SupplyRun sample shows the dual-field swap pattern, and nine sample scenes ship in the package (GettingStarted walks through them).

Which tier?

Two tiers, one deterministic native core. The rule is about targets, not headcount: agents heading to independent destinations (one path each) → Base, any number of them. A crowd sharing one — or a few — destinations (one field, many readers) → Pro. Pro builds on and depends on Base.

PathForge (Base)

Single-agent routing — QueryPath for one fast, exact path. All six graph adapters, the DnskPathFollower shortcut, and deterministic lockstep support.

PathForge Pro

Everything in Base plus shared fields — ComputeField / ComputeWeightedField for a crowd with one or a few targets, and BatchNextStep to resolve the whole group in a single native call per frame.
